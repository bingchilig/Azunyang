## 2. 원인 구분 — 관찰과 추정

### 확인한 사실
1. 직전 실패는 기존 joint의 geometryOrOriginTwo(target)를 먼저 갱신하는 setter에서 발생했다. 다음 geometryOrOriginOne(source) 재지정은 실행되지 않았다.
2. 직전 오류는 정확히 “RuntimeError: 3 : First component to move is grounded, it can not move.”였다.
3. 실패 후 읽은 기존 조인트의 실제 occurrenceOne은ACT_ref:3, 이 모터의Ground=false였다. ACT_ref:1과base_link만Ground=true였다.
4. 기존 geometryOrOrigin getter의assemblyContext는null이지만, 이 getter 결과만으로 실제 조인트가ACT_ref:1에 연결됐다고 판단할 수 없다.
5. 이번 신규 생성에서는 source proxy ACT_ref:3/:4, target proxy FL_abad_link:1, 입력 순서motor→link를 모두 확인했고 성공했다. 이후 회전 및computeAll에서도 연결이 유지됐다.

### 결론
**“입력 순서가 원인이었다” 또는 “ACT_ref:1로 해석된 것이 원인이었다” 중 어느 하나로 확정할 증거는 없다.**
이번에는 두 가지가 함께 바뀌었다: 기존 setter를 순차 갱신하는 방식 대신 두 proxy를 하나의 JointInput에 동시에 전달했고, 새 joint를 생성했다. 이 성공만으로 과거 오류의 원인을 분리할 수 없다.
공유 native JointOrigin을 기존 setter가재해석하는 과정에서 Ground된 기준 occurrence를 선택했을 가능성은 있으나 **추정**이다. 오류 당시 solver가 선택한 이름이 반환되지 않았다.
의도적으로 입력 순서를 뒤집거나 ACT_ref:1을 넣는 원인 재현 실험은 이번 승인 범위에 없으며 수행하지 않았다.
현재 조립 연결 복구/동작 검증 PASS와 과거 내부 원인 미확정은 별도로 기록한다.
